# Skillver DSH 插件(简历诊断部分）：测试后优化路线

## 结论

当前插件已具备最小可用闭环：配置 Key、简历与岗位差距分析、基于分析结果出题。已完成的本地验证中，22 个单元测试通过，设置卡片客户端构建通过；此前真实链路的 `ping → gap → questions` 也已成功。

但它目前仍偏向“把三个远程 API 暴露为工具”。用户需要依赖 Agent 猜对工具、岗位名和 `gapId`，结果以原始 JSON 呈现，缺少会话状态、隐私确认与失败恢复。产品目标应从“工具可调用”提升到“用户自然地完成简历诊断、补强与面试练习”。

## 目标体验

用户不需要知道 `skillver_ping`、`skillver_gap`、`skillver_questions` 或 `gapId`。理想流程是：

```text
用户：我的简历适合投 Agent 工程师吗？
  → Agent 确认简历、岗位和上传授权
  → 分析简历并保存本会话分析上下文
  → 用卡片解释是否建议投递、关键缺口和行动建议
  → 用户：根据刚才结果帮我练面试
  → 自动使用当前会话对应分析，逐题练习、评分和复盘
```

## P0：阻塞可用性、安全性与首次体验

### P0-1 岗位名发现与纠错

**问题**：岗位仅接受标准名称；输错空格、同义词或近似名称时，用户只得到“必须是标准岗之一”，不知道如何修正。

**建议**：

- 增加 `skillver_jobs`，返回标准岗位列表，并在插件端短期缓存。
- 服务端对非法岗位返回候选项/相似匹配，例如 `Agent 工程师 → Agent工程师`。
- Agent 在用户岗位不明确时先澄清或让用户确认候选，而不是直接调用分析。

**验收**：输入 `Agent 工程师`、`智能体开发工程师`、空岗位名时，用户都能在一次交互内得到可执行的下一步。

### P0-2 结果卡片化，不再直接输出 JSON

**问题**：三个工具均以 `JSON.stringify` 输出；求职者无法快速理解结论，Agent 也难以稳定转述嵌套字段。

**建议**：

- `gap`：呈现就绪度徽章、必须项覆盖率、关键缺口/优势分组、前三项行动建议和“开始练习”按钮。
- `questions`：以题号、技能标签、场景、任务要求和题集标识呈现；不要只显示原始对象。
- 保留原始 JSON 作为可展开的调试信息，不作为默认界面。
- 使用 DSH `output.render` 和 `presentationMeta` 提供结构化内容块与卡片。

**验收**：不阅读 JSON 的用户可以在 30 秒内回答“能不能投、差什么、下一步做什么”。

### P0-3 简历访问、上传前确认与校验

**问题**：当前路径直接用 `node:fs` 读取文件并上传，缺少大小、空文件和扩展名验证；还需确认其没有绕过 DSH 工作区与授权策略。

**建议**：

- 改用 DSH 文件系统/附件能力，确保文件访问受工作区范围和审批控制。
- 上传前说明“将把此简历发送到 Skillver 服务做分析”，显示文件名与大小，首次上传请求确认。
- 本地限制文件大小（例如 10 MB）、拒绝空文件，白名单 PDF/DOCX/DOC/TXT；未知类型不应静默伪装为 `text/plain`。

**验收**：越界路径、大文件、空文件、未知格式均在上传前得到明确提示；用户能取消上传。

### P0-4 发布包可直接启动

**问题**：包入口指向 TypeScript 源文件。已发布 DSH 需要额外 `NODE_OPTIONS=--import tsx/esm` 才能加载插件，普通 `dsh web` 不可用。

**建议**：构建并发布服务端 JavaScript 产物，将 `main` 与 `exports` 指向 `lib`；发布前在干净环境执行“安装 GitHub 插件 → dsh web”冒烟测试。

**验收**：全新 Windows 环境仅运行 README 的安装与启动命令即可使用，无额外加载器设置。

## P1：Agent 调度与求职闭环

### P1-1 用会话状态替代 gapId 暴露

**问题**：用户可能对新分析使用旧 `gapId` 出题，导致简历、岗位与题集串话。

**建议**：新增会话级 `skillver-context`：保存最近一次或多次分析的 `resumeFingerprint`、岗位、时间、`gapId` 与结果摘要。出题时默认使用当前会话、当前岗位的最新分析；有歧义才让用户选择简历/岗位，而不是输入 ID。

**验收**：连续分析两份简历后，说“根据刚才结果出题”会稳定命中最后一次分析；选择旧分析时界面明确展示对应简历与岗位。

### P1-2 重构工具调度语义

**问题**：`skillver_ping` 的描述要求“先调用”，这让 Agent 增加无意义调用，也将内部诊断暴露到用户工作流。

**建议**：

- `ping` 仅用于设置页“测试连接”或诊断，不作为普通对话前置步骤。
- 将工具描述写成用户意图：提到“简历、匹配、差距、能不能投”选择分析；提到“练习、面试题、模拟面试”选择当前会话分析出题。
- 提供一个高层编排能力，例如 `skillver_prepare`：分析 → 总结 → 生成首批练习 → 写入学习计划。低层工具仍保留给高级用户和调试。
- Agent 先补齐缺失的简历/岗位信息，再调用工具；不要求用户知道工具名。

**验收**：普通提示词“我的简历适合投什么岗位”“根据刚才结果练面试”均无需工具名或 ID 即可完成。

### P1-3 从出题走到答题与反馈

**建议**：

- 服务端返回参考答案、评分维度与常见遗漏，或新增 `skillver_answers` / `skillver_grade`。
- 引入“逐题作答 → 评分 → 追问 → 复盘”模式；DSH Agent 负责多轮对话，Skillver 负责题目、能力模型与评分。
- 每轮结束产出薄弱技能、建议复练题和下一步学习任务。

**验收**：用户可在同一会话完成一轮 3–5 题模拟面试，并拿到按技能归因的复盘。

### P1-4 多岗位对比与增量进步

**建议**：

- `skillver_compare`：同一简历对多个岗位输出覆盖率矩阵、推荐排序与投递建议。
- 依据简历指纹和岗位保留基线；重测时输出覆盖率变化、已消除/新增缺口。

**验收**：用户能回答“我更适合投哪个岗位”和“我改完简历是否变好”。

## P2：深度融入 DSH 生态

### P2-1 结果落盘与可追溯资源

将分析结果、练习题、评分复盘写入工作区 Markdown，例如 `skillver/Agent工程师-分析报告.md`。返回 DSH 文件引用，允许用户在会话中点击、继续编辑并在后续对话引用。

### P2-2 进度、超时与错误恢复

- 请求设置显式超时，组合超时信号与 DSH 取消信号。
- 对网络错误与安全可重试的 5xx 做有限重试；不重试可能重复创建的写操作。
- 统一错误码：未配置/失效 Key、岗位不合法、简历解析失败、限流、服务不可用；每种错误提供用户可执行的恢复动作和请求 ID。

### P2-3 国际化与部署配置

- 工具描述、参数错误和服务端错误映射均支持中文/英文，不能只本地化设置卡片。
- API 基址不应让终端用户随意编辑，但应提供部署级环境变量或注入 seam，支持测试、预发布与生产环境。
- Key 延续 `secret` 配置；支持环境变量 fallback，并在 UI 明确提示“此 Key 由启动环境提供，不能在此编辑”。

## P3：工程质量与可运营性

### 测试补齐

现有单元测试覆盖 Key 格式、配置优先级、设置卡片状态和工具注册，共 22 项；缺少以下关键场景：

- `client.ts` 的 mock fetch：401、422、429、5xx、超时、网络中断与异常 JSON。
- `resumeFile.ts` 的文件不存在、空文件、大小上限、格式与取消。
- DSH 端到端：自然语言路由、隐私审批、两份简历的会话隔离、旧 gapId 选择和出题数量边界。
- 发布冒烟：GitHub 安装、干净 profile、`dsh web`、设置卡片、首个工具调用。

### 发布与观测

- 使用语义化版本、CHANGELOG 和 GitHub Actions：测试、客户端构建、包内容审计、安装冒烟。
- 记录匿名化的调用耗时、失败码、岗位匹配失败率、从分析到练习的转化率；不要记录简历正文或 Key。
- 在结果卡片提供前往 jobver.net 完整报告的链接，并设计官网与 DSH 的进度同步边界。

## 推荐交付顺序

以下为一支小型产品与研发团队并行推进时的自然日估算。

1. **P0-1 + P0-2**：岗位发现与卡片化结果，直接改善首次体验。
2. **P0-3 + P0-4**：文件安全与可安装性，消除发布阻塞与隐私风险。
3. **P1-1 + P1-2**：会话上下文与自然语言调度，让用户不再知道工具名和 ID。
4. **P1-3 + P1-4**：答题反馈、多岗位对比和进步追踪，形成留存价值。
5. **P2/P3**：结果落盘、国际化、稳定性、测试与运营体系。
