# Skillver 学院(YATN)产品用户调研报告

> 数据来源：28位不同专业不同学校的受访者  
> 分析日期：2026-08-28  
## 一、结论摘要

Skillver 学院最值得验证的产品定位，不是“再做一套 AI 课程”，而是：

> **面向希望进入 AI 岗位、但缺少真实项目经历和工程闭环能力的人，提供真实项目、过程陪练、可信评审和可用于求职的成果证明。**

本轮调研呈现出五个稳定信号：

1. **用户真正想买的是“完成项目的确定性”，不是更多知识。** 23 位受访者都把“会用 AI”和“能做 AI 项目”的分界放在真实需求、系统设计、工程闭环和可交付结果上。
2. **最大障碍发生在实践过程，而不是内容获取。** 用户普遍能从 B 站、小红书、公众号、开源项目和大模型获得资料，但会卡在如何开始、架构设计、任务拆解、调试、质量验证及坚持完成。
3. **“能力测评”本身价值有限，必须连接解决方案。** 20位回答者都对泛化诊断提出条件：依据必须可信，结论不能只是复述岗位 JD，还要直接告诉用户如何补齐，并进入对应项目训练。
4. **真实企业项目与可信反馈是核心差异化。** 用户需要真实业务需求、企业案例、明确验收标准、行业专家或可信评审机制，以及可被面试官理解和认可的项目成果。
5. **产品内 AI 应是项目教练，而不是通用聊天框。** 它需要理解用户当前项目和代码，在卡点出现时解释原因、给出下一步、帮助拆解任务，并对结果的不确定性与准确度负责。

因此，首版产品应围绕一条最短闭环设计：

**能力与目标采集 →基础知识学习（不是最重要的）→ 匹配一项真实项目 → 分阶段交付 → AI 过程陪练 → 专家/规则评审。**

## 三、核心发现

### 1. 用户已有丰富的免费学习渠道，但缺少系统闭环

27 位回答学习方式的用户，全部以自助学习为主，来源包括 B 站、小红书、公众号、开源项目和大模型。现有渠道解决了“哪里能看到知识”，却没有解决：

- 应该按什么顺序学；
- 哪些技术是目标岗位真正需要的；
- 如何从业务需求拆成产品与工程任务；
- 遇到报错、架构或质量问题时如何继续；
- 怎样判断项目已经达到可交付标准。

这意味着 Skillver 不应与内容平台竞争“知识数量”，而应提供内容平台缺少的结构、反馈和交付约束。

### 2. 用户一致认为“学会AI”与“做成AI项目”的分界，是从工具使用转向真实交付
在 28 份相关回答中，受访者虽表达不同，但语义高度一致：

| “学会 AI/Agent” | “能够完成 AI/Agent 项目” |
| --- | --- |
| 会使用工具、模型或 Agent | 从真实用户/企业需求出发 |
| 能完成问答、分析或 Demo | 能做需求澄清、架构设计和任务拆解 |
| 让程序跑通 | 让系统跑好，并验证准确性与稳定性 |
| 获得知识或答案 | 交付一款对用户有收益的完整产品 |

用户要补齐的不是单个知识点，而是“需求—方案—实现—验证—交付”的完整链路能力。

### 3. 用户独立承担项目难点集中在启动、结构与质量

23 位回答“独立做项目最担心什么”的用户中：

- 18 位明确提到不知道如何开始、架构/模块边界不清或不会拆解任务；
- 5 位更集中担心“只能跑通、不能跑好”，以及 AI 输出准确性难以验证；
- 多位同时表达遇到困难容易放弃、缺少案例和及时指导。

这说明产品不能只在开头给一份学习路线。价值最密集的时刻，是用户已经开始做、但在某个具体节点卡住的时候。

### 4. 用户认可实战，但不信任泛化诊断

关于“能力差距诊断”的 20 份回答都带有明显条件：

- 不能只是把公开岗位 JD 换一种说法；
- 不能只指出差距而不给解决路径；
- 要说明评价依据、目标岗位标准和证据来源；
- 给建议的人或系统需要有真实成功案例、行业经验和可信度；
- 诊断结果最好直接连接训练项目和反馈机制。

因此，“AI 能力测评”更适合作为项目匹配和后续验证的入口，而不是关键卖点。用户最终相信的不是一张雷达图，而是完成任务前后的可观察能力变化。

### 5. 实战项目相对课程的价值非常明确，用户非常明确认为产品最有价值的就是看可以接触到企业实战项目

回答“与完成一门 AI 课程相比”的 28 位用户，全部认为亲手完成真实项目更有价值。理由包括：听课容易停留在被动输入，实战能形成真实需求经验、完整项目能力和可解释的过程。

用户对“证书”兴趣有限，更在意：

- 能否讲清楚自己做了什么、为什么这样做；
- 项目是否来自真实业务而非练习题；
- 结果是否经过可信评价；
- 能否包装为作品集，并在面试或入职考核中产生实际收益。

## 四、用户需求优先级

| 优先级 | 用户需求 | 本轮证据 | 产品含义 |
| --- | --- | --- | --- |
| P0 | 完成一个真实、完整、可交付的 AI 项目 | 25 位完整访谈均强调真实需求或工程闭环 | 产品核心不是课程目录，而是项目交付系统 |
| P0 | 在卡点获得具体、连续的过程指导 | 启动、架构、拆解、报错和放弃反复出现 | AI 需理解项目上下文并给出下一步行动 |
| P0 | 获得可信、可解释的项目评审 | 用户质疑通用 AI、JD 式诊断和输出准确性 | 建立评分标准、证据链与人工复核 |
| P0 | 产出可用于求职的作品和能力证明 | 用户更重视项目认可，而非证书 | 自动沉淀过程、决策、代码、结果和复盘 |
|  |
| P1 | 提供系统化、按需出现的知识 | 用户认为公开内容碎片化、行业变化快 | 知识应嵌入项目节点，而不是独立堆课 |
| P1 | 真实行业导师或技术专家反馈 | 多位用户将“真实经验”视为可信前提 | 在关键里程碑引入人工评审，不必全程1v1 |
| P2 | 陪伴、激励和防弃机制 | 多位用户提到卡住后容易放弃 | 用里程碑、同伴协作和及时反馈提高完课率 |

## 五、MVP 产品方案

### 核心产品闭环

1. **目标与能力采集**：读取简历、专业背景、项目经历和目标岗位，输出可解释的初始判断。
2. **项目匹配**：推荐 1 个难度合适的真实业务项目，明确业务背景、用户、交付物、约束与验收标准。
3. **里程碑拆解**：把项目拆为需求理解、方案设计、原型/开发、测试验证、交付复盘等阶段。
4. **AI 项目教练**：结合当前里程碑、代码仓库和历史决策，回答“为什么出错、下一步做什么、如何验证”，而不只是生成答案。
5. **可信评审**：每个关键节点按照公开 Rubric 评分，给出证据、改进项和复交要求；重要节点由行业导师抽检。
6. **成果沉淀**：自动生成项目说明、个人贡献、关键决策、测试结果、复盘和面试讲述稿，形成可分享作品集。

### AI 项目教练必须具备的能力

| 能力 | 具体要求 |
| --- | --- |
| 项目上下文记忆 | 知道用户当前目标、阶段、仓库、历史错误和已做决策 |
| 任务拆解 | 把模糊目标变成当前可执行的一步，并给出完成标准 |
| 报错辅导 | 解释错误原因，提供排查顺序，并引导用户亲手完成 |
| 边界与架构辅导 | 帮助区分产品模块、Agent 与传统软件边界、技术选型 |
| 质量验证 | 给出测试方法、准确性检查和风险提示，不把“能运行”等同于“可交付” |
| 证据与不确定性 | 标注判断依据、置信度和需要人工确认的部分 |
| 个性化补课 | 只在项目需要时补充对应知识，避免用户陷入漫长前置课程 |

### 必须做出的差异化

用户已能使用通用大模型和公开 JD，因此 Skillver 必须回答“为什么不直接问 AI”。建议把差异化集中在四项专有资产：

1. **经过授权和脱敏的真实企业项目库**；
2. **与岗位能力对应的项目 Rubric 和验收标准**；
3. **跨整个项目持续存在的上下文、过程证据与成长记录**；
4. **行业导师抽检及可被企业理解的成果认证。**

如果缺少这四项，产品很容易退化为“课程 + 聊天机器人”，正是受访者已经不缺、也最容易质疑的形态。

## 六、推荐的首版用户路径

| 阶段 | 用户动作 | 产品反馈 | 阶段成功标准 |
| --- | --- | --- | --- |
| 1. 定位 | 上传简历、选择目标方向 | 给出岗位建议、依据和待验证能力 | 用户选择一个目标岗位 |
| 2. 匹配 | 浏览并接受项目 | 展示项目真实性、难度、交付物和能力映射 | 用户确认项目并开始首个任务 |
| 3. 执行 | 按里程碑完成任务 | AI 拆解、答疑、调试和知识补给 | 每周持续产生可检查交付物 |
| 4. 评审 | 提交阶段成果 | Rubric 评分、证据、修改建议、导师抽检 | 达到阶段通过线或完成复交 |
| 5. 证明 | 完成复盘和项目答辩 | 生成作品集、能力变化和面试讲述稿 | 用户能独立讲清项目完整过程 |
| 6. 求职验证 | 在投递、面试中使用成果 | 收集面试反馈并反哺能力图谱 | 获得面试推进或岗位能力认可 |

## 七、关键指标

首版不要用“看了多少课”作为北极星指标，建议围绕交付闭环衡量：

| 指标层级 | 建议指标 |
| --- | --- |
| 激活 | 注册后 24 小时内接受项目并完成第一项任务的比例 |
| 过程 | 7 日持续率、里程碑按期提交率、卡点后继续推进率 |
| 交付 | 项目完整交付率、首次评审通过率、复交后提升幅度 |
| 能力 | 各能力项前后测变化、用户能否独立解释关键决策 |
| AI 价值 | AI 建议采纳率、问题解决率、错误建议率、转人工率 |
| 求职价值 | 作品集使用率、面试提及率、面试推进率、入职后反馈 |
| 信任 | 评审可信度评分、项目真实性评分、导师与系统评分一致性 |

推荐的北极星指标是：

> **在规定周期内完成一个达到公开验收标准、并能由用户独立讲清的真实 AI 项目的活跃用户比例。**

## 八、主要风险

1. **真实项目名不副实**：如果项目只是包装后的练习题，会直接损害最核心的信任。应公开项目来源类型、业务背景、脱敏方式和验收方。
2. **AI 陪练退化为答案生成器**：用户可能复制代码完成表面交付，却没有形成能力。需要让 AI 先诊断、解释和提问，再提供分层提示。
3. **评审缺少公信力**：纯 AI 评分会被质疑。关键节点需要可追溯的 Rubric、示例答案和人工抽检。
4. **导师(可以初期先是公司开发们）供给成本过高**：全程一对一难以规模化。可采用 AI 日常陪练、同伴互评、导师关键节点抽检的组合。
5. **作品知识产权与数据安全**：已有受访者明确担心知识产权。企业项目、用户代码和作品展示都需要清晰授权、隔离与可撤回机制。
6. **目标人群过宽**：AI 产品、Agent 工程、大模型算法和 FDE 的能力结构差异明显。首版应先选一个岗位与项目类型做深，再扩展路径。

## 九、最终产品判断

当前最有证据支持的方向，是把 Skillver 学院设计为一套 **“真实 AI 项目交付与能力证明系统”**。课程只是项目过程中的按需资源；AI 只是过程教练；真正形成壁垒的是项目真实性、持续上下文、可信评审和求职结果。

首版建议聚焦一个岗位、一类项目和一个完整闭环。只要能证明用户可以从“不知道如何开始”，走到“独立完成、通过评审、能在面试中讲清”，产品就建立了比普通 AI 课程更清晰的价值。
